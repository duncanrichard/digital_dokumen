# Laporan QA sistem dokumen — 21 September 2026

## Status perbaikan

Perbaikan kode telah diterapkan pada 21 September 2026:
- Eskalasi role Superadmin dibatasi dan role utama kini disinkronkan ke pivot Spatie.
- Perubahan, penghapusan, pembuatan, perubahan turunan, dan revisi dokumen dibatasi pada divisi pemilik kecuali Superadmin.
- Token Fonnte dipindahkan ke `FONNTE_TOKEN`; token lama harus dirotasi melalui dashboard Fonnte sebelum rilis.
- Gallery menghasilkan PDF watermark dan menghapus salinan sementara setelah dikirim.
- Login dibatasi lima percobaan per menit per alamat IP.
- Notifikasi approver memakai role utama yang sama dengan otorisasi aplikasi.
- User tanpa divisi hanya melihat dokumen yang didistribusikan langsung kepadanya; penghapusan file dilakukan setelah database commit.
- Jalur create dan revisi membersihkan file upload jika transaksi database gagal.
- Permission baca dipisahkan dari aksi: `documents.distribution.update`, `documents.revisions.create`, dan `documents.access-approvals.decide`. Permission baru telah didaftarkan ke database dan perlu diberikan kepada role yang berwenang melalui Pengaturan Permission.
- Distribusi dan statistik kontrol dokumen kini hanya memakai dokumen yang terlihat atau dimiliki oleh pengguna; pengelola role non-Superadmin tidak dapat membuat bypass dengan mengganti nama role menjadi `Superadmin`.

## Kesimpulan dan cakupan

Belum layak dinyatakan lolos QA untuk produksi. Pemeriksaan kode menemukan masalah otorisasi dan perlindungan dokumen. Temuan di bawah adalah hasil penelusuran kode, bukan klaim eksploitasi terhadap data nyata.

Pemeriksaan yang dijalankan:
- `php artisan test`: 2 tes lulus, 2 assertions. Tes hanya memeriksa true=true dan respons HTTP 200 halaman login.
- `php artisan route:list --except-vendor --json`: berhasil memuat rute aplikasi.
- `php -l`: 185 file PHP di app, routes, config, database, dan tests lolos pemeriksaan sintaks.
- Review login, pengelolaan user, akses dokumen, revisi, watermark, notifikasi, dan pencarian AI.

Masih perlu dilakukan di lingkungan rilis: rotasi token Fonnte yang lama, memasang `FONNTE_TOKEN`, pengujian browser dengan akun tiap role, pengiriman notifikasi eksternal, build frontend, pengujian beban, dan audit dependensi. Perubahan awal pada `.gitignore` dan `ai_service/main.py` dipertahankan.

## Temuan prioritas

### 1. P1 — Pengelola user dapat menaikkan role menjadi Superadmin

Lokasi: `app/Http/Controllers/Access/UserController.php:233` dan `:289` (juga jalur create pada :152 dan :210).

Middleware hanya mensyaratkan `access.users.update` untuk update. Validasi `role_id` hanya memeriksa keberadaan role; tidak membatasi assignment Superadmin, perubahan diri sendiri, atau perubahan akun berprivilege lebih tinggi. Role kemudian disimpan langsung dan dipakai sebagai bypass pada controller lain.

Skenario verifikasi di database uji: login sebagai non-Superadmin dengan izin update user, kirim update untuk akun sendiri dengan role_id Superadmin dan field valid lainnya. Seharusnya 403 dan role tidak berubah.

Perbaikan: otorisasi assignment role secara eksplisit; hanya Superadmin yang dapat memberikan role Superadmin atau mengubah akun Superadmin.

### 2. P1 — Edit/hapus dokumen tidak memeriksa cakupan divisi

Lokasi: `app/Http/Controllers/Documents/DocumentUploadController.php:430`, `:446`, `:532`.

Daftar dokumen dibatasi menurut divisi pada :178, tetapi route model binding edit/update/destroy menerima dokumen global. Middleware hanya memeriksa permission fitur; method tidak memeriksa kepemilikan/divisi dokumen. Pengguna dengan permission update/delete dapat menargetkan ID dokumen divisi lain meskipun tidak muncul di daftarnya.

Skenario verifikasi: buat dokumen di divisi B dan user divisi A yang punya izin update/delete; akses edit atau kirim perubahan ke ID dokumen B. Harus ditolak sebelum membaca detail atau memodifikasi file/data.

Perbaikan: policy per dokumen yang membedakan izin membaca dokumen terdistribusi dan izin mengubah/menghapusnya.

### 3. P1 — Token layanan WhatsApp tersimpan langsung di source

Lokasi: `app/Http/Controllers/Documents/DocumentDistributionController.php:22`.

Controller berisi literal token Fonnte. Nilainya tidak disalin ke laporan. Setiap pihak yang memperoleh source dapat memperoleh kredensial tersebut; validitas token belum diuji.

Perbaikan: pindahkan ke konfigurasi environment dan rotasi token yang pernah tersimpan di repository. Penghapusan literal saja tidak mencabut token lama.

### 4. P2 — Gallery mengabaikan konfigurasi watermark

Lokasi: `app/Http/Controllers/Documents/DocumentGalleryController.php:367`; pemanggil `resources/views/documents/access-requests/open.blade.php:140`.

Pembaca PDF mengambil `documents.gallery.file.raw`, yang mengembalikan file asli langsung dari storage. Endpoint ini memeriksa akses, tetapi tidak membaca pengaturan atau menjalankan proses watermark. Jalur upload mempunyai implementasi watermark terpisah pada `DocumentUploadController.php:654`.

Skenario verifikasi: aktifkan watermark, buka dokumen PDF yang sama melalui Gallery, periksa respons PDF. Watermark yang dikonfigurasi seharusnya ikut diterapkan.

Perbaikan: gunakan satu service penyajian PDF dengan otorisasi dan watermark yang konsisten.

### 5. P2 — Login tidak memiliki pembatasan percobaan di aplikasi

Lokasi: `routes/web.php:58`; `app/Http/Controllers/authentications/LoginBasic.php:22`.

POST login tidak memakai middleware throttle dan controller tidak memakai rate limiter/lockout. Middleware global/web juga tidak menambahkan limiter. Percobaan password berulang tidak dibatasi oleh aplikasi. Pembatasan pada reverse proxy belum diperiksa.

Perbaikan: pembatasan berdasarkan username dan IP, dengan reset yang sesuai setelah login berhasil. Verifikasi pada lingkungan uji bahwa percobaan berulang mendapat respons 429/lockout.

### 6. P2 — Notifikasi approver memakai relasi role yang berbeda

Lokasi: `app/Http/Controllers/Documents/DocumentGalleryController.php:301`.

Penerima notifikasi dipilih melalui `roles.permissions` milik Spatie, sedangkan pengelolaan user menyimpan `users.role_id` dan otorisasi approval memakai relasi `role`. Tidak ditemukan sinkronisasi `assignRole`/`syncRoles` dalam jalur pengelolaan user. User yang diberi role approver lewat UI dapat mengakses approval, tetapi tidak masuk daftar penerima notifikasi realtime.

Perbaikan: konsisten menggunakan satu sumber role atau sinkronkan pivot Spatie secara atomik saat role diubah. Verifikasi dengan approver baru yang dibuat melalui UI.

### 7. P2 — User tanpa divisi mendapat daftar dokumen semua divisi di halaman kontrol

Lokasi: `app/Http/Controllers/Documents/DocumentControlController.php:18`.

Filter akses hanya dijalankan jika department_id terisi. User biasa tanpa divisi memperoleh seluruh dokumen aktif dalam query visible dan daftar terbaru, walaupun file tetap mempunyai pemeriksaan akses tersendiri. Pembuatan user memang mengizinkan department_id null.

Perbaikan: default query harus membatasi akses; distribusi langsung ke user tetap diperiksa meskipun user tidak punya divisi. Bypass global harus eksplisit hanya untuk role yang berhak.

### 8. P2 — Penghapusan file mendahului keberhasilan transaksi database

Lokasi: `app/Http/Controllers/Documents/DocumentUploadController.php:508` dan `:535`.

Update menghapus file lama sebelum sinkronisasi distribusi selesai; destroy menghapus file sebelum detach/delete database. Jika operasi database berikutnya gagal, rollback mengembalikan record tetapi tidak dapat mengembalikan file fisik yang sudah dihapus. Dokumen dapat menunjuk ke file yang hilang.

Perbaikan: jadwalkan penghapusan file lama setelah commit; bersihkan file baru jika transaksi gagal. Verifikasi melalui injeksi kegagalan database pada lingkungan uji.

## Urutan tindak lanjut

1. Tutup eskalasi role dan akses tulis dokumen lintas divisi; rotasi token.
2. Samakan jalur watermark dan relasi role, batasi login, perbaiki filter user tanpa divisi dan konsistensi file/database.
3. Tambahkan tes regresi berbasis skenario di atas dengan database pengujian terpisah. `phpunit.xml` saat ini belum mengaktifkan konfigurasi database uji terisolasi.
4. Jalankan QA browser untuk upload, revisi, distribusi, approval, expiry akses, pencarian, serta akun aktif/nonaktif pada setiap role.
